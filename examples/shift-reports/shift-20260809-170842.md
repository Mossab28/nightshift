**Root cause (one, not five):** silent schema break on `order_date`, not on revenue. `order_total` is FLOAT and intact at every hop. But `order_entry.orders.order_date` is **TEXT**, the dbt `order_details` model selects it **uncast**, so `analytics.order_details.order_date` lands in Snowflake as VARCHAR - while the model's own docs promise TIMESTAMP_TZ. Power BI's `Essential_KPI_Measures` does all its time-intelligence (`DATESYTD`, `SAMEPERIODLASTYEAR`, date slicers) on that column; date-filtering a text column matches zero rows, so `SUMX(order_total)` sums an empty table. Zero revenue, no failed job, nobody paged until Finance looked. What would disprove it: pull one row of `order_date` from Snowflake - if it comes back as a real timestamp, I'm wrong.

**Fix:** in the dbt model - `TO_TIMESTAMP_TZ(o.order_date) AS order_date`. Rebuild, refresh the PBI dataset. `dispatch_date`, `return_date`, `estimated_delivery` are TEXT too - same latent bug, follow-up ticket for Data Platform (Maya Patel's team; escalation contact Ben Porter).
